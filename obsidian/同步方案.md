# 同步方案

怎么让这个仓库的笔记出现在本机 Obsidian 库里，并且**保持干净、自动更新**。

方案是 **sparse checkout + launchd 定时 pull + 本机 Claude Code 直写**（当时讨论里的 ④+③ 组合）。

## 一条命令配好

```bash
git clone https://github.com/Lee-Claude/cangjie-skill.git ~/code/cangjie-skill
cd ~/code/cangjie-skill
./scripts/setup-obsidian-sync.sh ~/文稿/Obsidian
```

脚本是幂等的，重复跑只会更新，不会重复 clone 或重复注册定时任务。

## 架构

```
        GitHub 仓库  ← 单一真相源
        ↙                    ↘
~/code/cangjie-skill      ~/文稿/Obsidian/AI工作台
  全量 clone                 sparse checkout（只有 obsidian/）
  写代码用                    launchd 每 15 分钟自动 pull
```

两边推同一个仓库，不会分叉。

## 为什么是这套

三条原则各自对应一个技术选择：

**统一知识库** → 笔记直接落在 Obsidian 库内部，和其他笔记共享同一个搜索、同一张关系图谱。不是"另开一个应用去看"。

**不要乱** → `git sparse-checkout set --no-cone '/obsidian/'`。工作区只有 `.git` 和 `obsidian/`，实测 344K，`workbench/` 的代码**一个字节都不会落盘**——不是隐藏，是根本不下载。

> `--no-cone` 是关键。默认的 cone 模式会把仓库根目录的 `README.md`、`SKILL.md`、`README.ja.md` 也拉下来，6 个无关文件进库，那就不干净了。第一次实测就踩了这个。

**自动化** → launchd 每 15 分钟静默 pull，开机自动加载。用 launchd 而不是 cron，因为它在睡眠唤醒后会补跑。

## 排除掉的方案

| 方案 | 为什么不用 |
| --- | --- |
| 软链仓库目录进库 | Obsidian 默认不跟随软链的文件变化，要开「检测所有文件变化」（大库会卡）；iCloud 不同步软链 |
| 整个仓库 clone 进库 | 代码进 Obsidian 文件树和搜索；一旦在库里 `npm install`，`node_modules` 几万个文件会让索引器卡死 |
| Obsidian Git 插件 | 它管的是**库根目录**那个仓库。库根不该是这个项目的仓库（里面还有别的笔记），子目录里的独立仓库它管不到 |

## 坑

### iCloud + git = 仓库损坏

macOS「桌面与文稿文件夹」同步开着的话，`~/文稿` 就在 iCloud Drive 里。iCloud 的**「优化储存空间」会把不常访问的文件抽成占位符**，`.git` 里的 object 被抽走就是仓库损坏；多设备同步还会在 `.git` 里产生冲突副本。

Obsidian 官方也不建议库放 iCloud。**建议把库移出 iCloud**。脚本会检测路径并警告。

### 多一层嵌套

sparse checkout 保留仓库内的路径结构，所以笔记实际在：

```
~/文稿/Obsidian/AI工作台/obsidian/热点聚合.md
                ↑ clone 的目录  ↑ 仓库里的目录名
```

多一层 `obsidian/`。不影响搜索和图谱，只是面包屑有点冗余。

改法：`FOLDER_NAME=xxx ./scripts/setup-obsidian-sync.sh ~/文稿/Obsidian` 换掉外层名字。

想彻底去掉这层嵌套，得开一个只含笔记的 orphan 分支（笔记直接在分支根目录），再用 GitHub Action 从 `obsidian/` 同步过去。多了一套机器，暂时没做——一层嵌套换零维护成本，划算。

### PR 合并前分支不对

笔记目前在 `claude/personal-ai-dashboard-adxhu5` 分支上，脚本默认拉 `main`。PR 合并前要指定分支：

```bash
BRANCH=claude/personal-ai-dashboard-adxhu5 ./scripts/setup-obsidian-sync.sh ~/文稿/Obsidian
```

合并后直接用默认值。

## 日常操作

| 想做什么 | 命令 |
| --- | --- |
| 手动同步一次 | `git -C ~/文稿/Obsidian/AI工作台 pull` |
| 看自动同步有没有报错 | `cat /tmp/com.lee.obsidian-pull.err` |
| 暂停自动同步 | `launchctl unload ~/Library/LaunchAgents/com.lee.obsidian-pull.plist` |
| 改同步间隔 | 改 plist 里的 `StartInterval`（秒），然后 unload + load |
| 在库里改了笔记想推回去 | `cd ~/文稿/Obsidian/AI工作台 && git add -A && git commit -m "..." && git push` |

定时任务用的是 `git pull --rebase --autostash`，所以你在库里本地改了笔记还没提交，自动同步也不会冲突或丢东西。

## 本机 Claude Code 那一半

在 `~/code/cangjie-skill` 里跑 Claude Code：代码和笔记都能看到，写完 push，15 分钟内自动出现在库里。

也可以直接在 `~/文稿/Obsidian/AI工作台` 里跑——好处是写完立刻可见，但**它只能看到笔记，看不到 `workbench/` 的代码**（sparse checkout 的必然结果）。所以：**改代码去全量 clone，纯写笔记两边都行。**
