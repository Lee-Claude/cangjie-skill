# 同步方案

怎么让这个仓库的笔记出现在本机 Obsidian 库里，并且**保持干净、自动更新**。

方案是 **sparse checkout + launchd 定时 pull + 本机 Claude Code 直写**（当时讨论里的 ④+③ 组合）。

## 一条命令配好

```bash
# PR #1 合并前脚本还在功能分支上，clone 要带 -b；合并后去掉即可
git clone -b claude/personal-ai-dashboard-adxhu5 \
  https://github.com/Lee-Claude/cangjie-skill.git ~/code/cangjie-skill
cd ~/code/cangjie-skill
./scripts/setup-obsidian-sync.sh ~/Obsidian
```

脚本是幂等的，重复跑只会更新，不会重复 clone 或重复注册定时任务。

## 架构

```
        GitHub 仓库  ← 单一真相源
        ↙                    ↘
~/code/cangjie-skill      ~/Obsidian/AI工作台
  全量 clone                 sparse checkout（只有 obsidian/）
  写代码用                    launchd 每 15 分钟自动 pull
```

两边推同一个仓库，不会分叉。

## 为什么是这套

三条原则各自对应一个技术选择：

**统一知识库** → 笔记直接落在 Obsidian 库内部，和其他笔记共享同一个搜索、同一张关系图谱。不是"另开一个应用去看"。

**不要乱** → `git sparse-checkout set --no-cone '/obsidian/'`。工作区只有 `.git` 和 `obsidian/`，实测 344K，`workbench/` 的代码**一个字节都不会落盘**——不是隐藏，是根本不下载。

> `--no-cone` 是关键。默认的 cone 模式会把仓库根目录的 `README.md`、`SKILL.md`、`README.ja.md` 也拉下来，6 个无关文件进库，那就不干净了。第一次实测就踩了这个。

**自动化** → launchd 每 15 分钟静默 pull，开机自动加载。用 launchd 而不是 cron，因为它在睡眠唤醒后会补跑。

## 排除掉的方案

| 方案 | 为什么不用 |
| --- | --- |
| 软链仓库目录进库 | Obsidian 默认不跟随软链的文件变化，要开「检测所有文件变化」（大库会卡）；iCloud 不同步软链 |
| 整个仓库 clone 进库 | 代码进 Obsidian 文件树和搜索；一旦在库里 `npm install`，`node_modules` 几万个文件会让索引器卡死 |
| Obsidian Git 插件 | 它管的是**库根目录**那个仓库。库根不该是这个项目的仓库（里面还有别的笔记），子目录里的独立仓库它管不到 |

## 坑

### iCloud + git = 仓库损坏

macOS「桌面与文稿文件夹」同步开着的话，`~/Documents` 就在 iCloud Drive 里。iCloud 的**「优化储存空间」会把不常访问的文件抽成占位符**，`.git` 里的 object 被抽走就是仓库损坏；多设备同步还会在 `.git` 里产生冲突副本。

Obsidian 官方也不建议库放 iCloud。脚本会检测路径并警告。

**迁出步骤见 [[库放在哪]]** —— 关键是别去关「桌面与文稿文件夹」开关（会丢数据），只把库单独挪到 `~/Obsidian`。

### 多一层嵌套

sparse checkout 保留仓库内的路径结构，所以笔记实际在：

```
~/Obsidian/AI工作台/obsidian/热点聚合.md
                ↑ clone 的目录  ↑ 仓库里的目录名
```

多一层 `obsidian/`。不影响搜索和图谱，只是面包屑有点冗余。

改法：`FOLDER_NAME=xxx ./scripts/setup-obsidian-sync.sh ~/Obsidian` 换掉外层名字。

**为什么不去掉这层嵌套**：唯一的办法是开一个只含笔记的 orphan 分支（笔记直接在分支根目录），再用 GitHub Action 从 `obsidian/` 同步过去。但那样**库里的副本就变成只读的**——你在 Obsidian 里改了笔记 push 回去，下次 Action 从 main 同步会把你的修改覆盖掉。

知识库是要随手改的，为了少一层面包屑牺牲双向编辑不划算。sparse checkout 的副本是真实分支的正常 checkout，改完 `git push` 就回去了。所以保留这层嵌套。

### 分支：clone 要带 `-b`，脚本参数不用管

踩过一次：`git clone` 不带 `-b` 拿到的是 `main`，而**脚本本身只在功能分支上**，于是
`./scripts/setup-obsidian-sync.sh` 直接报 `no such file or directory`。

现在脚本会**自动用它自己所在的分支**作为拉笔记的分支（`git rev-parse --abbrev-ref HEAD`，
detached HEAD 时退回 `main`），所以只要 clone 对了分支，后面就不用传 `BRANCH=`。

要覆盖的话仍然可以：`BRANCH=某分支 ./scripts/setup-obsidian-sync.sh ~/Obsidian`。

## macOS 实测记录（2026-08-08）

在 lee 的 Mac 上跑通了，全绿。过程中踩了三个坑，**全都是只在 macOS 上才暴露的**，
Linux 容器里怎么测都测不出来。换机器时照着避一遍：

### 1. `~/文稿` 在终端里不存在

「文稿」只是 Finder 显示的中文名，文件系统里是 `~/Documents`。`cd ~/文稿` 直接报错。

### 2. clone 不带 `-b` 会落在没有脚本的分支上

`git clone` 默认拿 `main`，而脚本当时只在功能分支上，于是
`./scripts/setup-obsidian-sync.sh` 报 `no such file or directory`。

已改成脚本自动读取自己所在分支，但 **clone 那一步的分支还是要自己给对**。

### 3. 变量后面紧跟中文全角标点会炸

```
./scripts/setup-obsidian-sync.sh: line 82: BRANCH?: unbound variable
```

`$BRANCH）` 里那个全角右括号首字节是 `0xEF`，老版 bash 把它吞进了变量名，
于是去找一个不存在的 `BRANCH\xEF…`，撞上 `set -u` 直接退出。终端把那个字节渲染成 `?`。

实测本机版本：

```
$ bash --version | head -1
GNU bash, version 3.2.57(1)-release (arm64-apple-darwin25)
```

**2007 年的 bash 跑在 2026 年的 ARM Mac 上** —— Apple 因为 GPLv3 一直没升级自带的 `/bin/bash`，
它的多字节处理有缺陷。bash 5 下同样的代码怎么试都不复现，所以这个坑只会在 macOS 上炸。

（严格说：版本是实测的，「首字节被吞进变量名」这个机制是从错误信息 `BRANCH?` 里那个
渲染不出来的字节推断的 —— 但加花括号之后就好了，结论上没有分歧。）

> 想彻底绕开这类问题可以 `brew install bash` 装个 5.x，但脚本本身已经兼容 3.2，不装也行。

**写这类脚本的规矩：变量后面只要跟着中文标点，一律写 `${VAR}`。**
脚本里三处都改了并留了注释，扫描命令：

```bash
grep -nP '\$[A-Za-z_][A-Za-z0-9_]*[\x80-\xff]' 脚本路径
```

### 顺带确认的

- 幂等性在真机上验证过：第二次跑走的是「已存在，跳过 clone」
- 脚本没用到 bash 4+ 语法，3.2 能跑
- launchd 注册成功（这是唯一没法在容器里验的环节）

## 日常操作

| 想做什么 | 命令 |
| --- | --- |
| 手动同步一次 | `git -C ~/Obsidian/AI工作台 pull` |
| 看自动同步有没有报错 | `cat /tmp/com.lee.obsidian-pull.err` |
| 暂停自动同步 | `launchctl unload ~/Library/LaunchAgents/com.lee.obsidian-pull.plist` |
| 改同步间隔 | 改 plist 里的 `StartInterval`（秒），然后 unload + load |
| 在库里改了笔记想推回去 | `cd ~/Obsidian/AI工作台 && git add -A && git commit -m "..." && git push` |

定时任务用的是 `git pull --rebase --autostash`，所以你在库里本地改了笔记还没提交，自动同步也不会冲突或丢东西。

## 本机 Claude Code 那一半

在 `~/code/cangjie-skill` 里跑 Claude Code：代码和笔记都能看到，写完 push，15 分钟内自动出现在库里。

也可以直接在 `~/Obsidian/AI工作台` 里跑——好处是写完立刻可见，但**它只能看到笔记，看不到 `workbench/` 的代码**（sparse checkout 的必然结果）。所以：**改代码去全量 clone，纯写笔记两边都行。**
