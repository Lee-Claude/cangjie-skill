# 创作模板

[[AI 工作台]] 的写作预设。代码在 `lib/prompt.ts`，改文案直接改那个文件。

## 五个模板

| 模板 | 写作要求要点 |
| --- | --- |
| 自由对话 | 不追加任何要求 |
| 推特长文 | 第一条必须独立成立且让人想点开；每条一个论点；不堆编号符号；不用 emoji 开头；避免营销腔；事实和观点分开 |
| 公众号 | 标题给 3 个备选；小标题分段；开头两句交代清楚发生了什么、为什么现在值得看；禁止"在这个 AI 飞速发展的时代"这类空话 |
| 短视频脚本 | `[画面]` / `[口播]` 两栏；前 3 秒给钩子；60 秒约 180 字口播；短句，能念出来 |
| 深度拆解 | 一句话说清事件；分技术 / 商业 / 影响三层；明确区分"报道写了的"和"你的推断"；不确定就说不确定 |

## 底层 system prompt

所有模板都叠在这段之上：

```
你是一个 AI 赛道创作者的工作台助手，正在一个实时热点面板旁边和用户对话。

要求：
- 用中文回答，除非用户用其他语言提问。
- 直接给结果，不要开场白和"好的，我来帮你"这类铺垫。
- 涉及热点事实时，只依据下面提供的热点条目；条目里没有的信息，说明这是你的推断
  或建议用户去核实，不要编造数字、引述和链接。
- 写作类任务给可直接使用的成稿，不要给"你可以这样写"的元描述。
```

第三条是重点。热点面板给的是标题 + 摘要，模型很容易顺手补一个看起来合理的融资金额或引述。**明确划定"只能用给你的条目"这条线**，比事后校对省事得多。

第四条针对的是模型爱写"你可以这样开头：……"的毛病 —— 要的是成稿，不是写作指导。

## 热点怎么进上下文

勾选的条目拼成 system prompt 里的一个块，最多 10 条：

```
## 用户选中的热点条目（共 1 条）
1. Spotify 前员工筹集 1000 万美元，将人工智能引入电子商务建议
   来源：AI 热榜 · 📰 新闻
   链接：https://techcrunch.com/2026/08/06/...
   时间：2026-08-06
   摘要：该初创公司的平台可以预测购物者接下来想要什么产品……
```

链接带上是有意的 —— 模型引用时能给出真实出处，而不是编一个。

## 加模板

在 `TEMPLATES` 数组里加一项：

```ts
{
  key: "xiaohongshu",
  label: "小红书",
  starter: "把选中的热点写成一篇小红书笔记。",   // 点击时填进输入框的初稿
  system: "写小红书笔记时：……",                  // 追加到 system prompt
}
```

`starter` 是给人看的（降低"面对空输入框不知道说什么"的摩擦），`system` 是给模型看的。两者不要写重复内容。
