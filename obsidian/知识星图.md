# 知识星图

[[AI 工作台]] 的第二个视图。参考了 [oyorf/person_dashboard](https://github.com/oyorf/person_dashboard)
的"知识星图 + Wiki 层"创意，直接读取本地 Obsidian vault，把笔记之间的 wikilink 画成关系图。

## 为什么先做这个，不做别的

那个项目公开仓库里，社媒洞察 / 抖音数据 / 公众号这几个模块**其实没有实现代码**——作者自己在
README 里写明是"私有/未发布模块"。所以"借鉴"这几块无从谈起，只能照着截图从零设计，跟看着一张
效果图新做一个功能没有本质区别。

真正有公开实现、而且能立刻用上真数据的，只有知识图谱这一块——而且我们现在自己就有一个
`obsidian/` vault（这份笔记本身），wikilink 已经在用了，不用等别的模块打基础。所以先做这个。

## 架构决定

**workbench 必须能读本机文件系统才做得了这个** —— 这跟它原来"纯 API 聚合、可部署到任意
serverless 环境"的定位不完全一样了。好在 workbench 本来就是设计成 `npm run dev` 本机跑的
（README 里写的就是这个），加文件系统访问是自然延伸，不是推翻重来。

**Vault 根路径默认指向仓库自己的 `../obsidian`。** 不用配置任何环境变量，`npm run dev`
起来就有真实数据——这些笔记本来就是这个项目自己的文档，是个完美的自举 demo。想指向别的
vault（比如未来真正的个人知识库），设 `VAULT_ROOT` 覆盖。

## 技术实现

### Frontmatter 解析器是手写的，不是 gray-matter

跟 `components/Markdown.tsx` 一个思路：frontmatter 格式很简单（标量 + 一层列表），
没必要为几行 YAML 引入完整解析库。`lib/vault/frontmatter.ts` 大概 50 行。

### 死链接靠"过滤"处理，不靠"识别代码块"

`CLAUDE.md` 和 `README.md` 里有大量作为**示例文本**写的 `[[上级笔记]]`、`[[双链]]`——
这些不是真链接，是教人怎么写 frontmatter 的占位符。要不要把它们排除在图谱之外？

严谨做法是先跳过围栏代码块和行内代码再提取 wikilink（`extractWikilinkTargets` 确实这么做了），
但这解决不了表格、反引号之外裸写的示例文本。真正兜底的是**第二道过滤**：解析出的链接目标
如果在 vault 里找不到对应的笔记，直接丢弃，不生成边、不创建幽灵节点。

这样"上级笔记.md"根本不存在，示例文本自然被过滤掉，不需要判断"这是不是示例"——不存在的
笔记，链接它就是死链接，逻辑上没有例外情况要特殊处理。

### 力导向布局是手写的，不是 d3-force

`lib/vault/layout.ts`，简化版 Fruchterman-Reingold，~100 行，服务端算好坐标（归一化到
0–1）一次性返回，前端纯渲染不用再引入图形库。笔记数量级是几十到几百篇，手写实现够用。

初始布局故意用**确定性伪随机**（对 slug 字符串做简单哈希）而不是 `Math.random()`——
同一个 vault 每次请求应该给出同一张图，不然节点每次刷新都要重新抖动，体验很差。

### 正文里的双链要能点，不只是图谱节点能点

第一版做完图谱可视化后自测发现：笔记详情页正文里的 `[[热点聚合]]` 被 Markdown 渲染器当成
纯文本原样吐出来了，方括号都在，点不动。图谱节点能点、正文双链不能点，这样"知识图谱"名不副实。

`components/Markdown.tsx` 是给 AI 对话消息设计的零依赖渲染器，不认识 `[[wikilink]]` 语法。
修复思路：

1. `GET /api/vault/[slug]` 额外返回 `linkResolution: Record<string, string | null>`——
   正文里每个 `[[原始写法]]` 精确对应到 slug（或 `null` 表示死链接）。不能复用
   `note.links`，那是已经去重、去自环的图谱边，丢了"原始写法 → 目标"的对应关系。
2. `Markdown` 组件加两个可选 prop：`resolveWikilink` 查目标，`onWikilinkClick` 点击回调。
   死链接渲染成灰色不可点的 `[[标题]]`，不是彻底隐藏——用户知道"这里想链接但目标不存在"，
   而不是看到一段莫名其妙消失了方括号的文字。
3. 正则顺序有个坑：`[[...]]` 和 `[...](...)` 都以 `[` 开头，如果普通链接的分支排在
   wikilink 前面，会把 `[[热点聚合]]` 的内层 `]` 错认成自己的收尾。wikilink 分支必须
   排在普通链接分支之前。

### 为什么图谱和列表要联动高亮

选中一个节点后，非邻居的节点和边会淡化（`opacity` 降到 0.35），左侧列表和右侧详情
同步高亮当前选中项。这不是装饰——笔记一多，光看图谱的连线很难看出"这个节点到底连了谁"，
高亮把"这篇笔记的邻域"从视觉噪音里单独摘出来。
