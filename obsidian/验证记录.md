# 验证记录

[[AI 工作台]] 到底验到什么程度。写下来是为了以后自己心里有数 —— 哪些是真跑过的，哪些是只写了没试过的。

## 验过的

**生产构建** —— `next build` 通过，TypeScript 无报错。

**界面** —— Playwright 实跑：勾热点 → 选模板 → 发消息 → 流式渲染，全程控制台零报错。

**[[数据源 - AI hot|AI 热榜]]** —— 对真实数据验过。拉到 10 条热榜 + 当天简报，时间衰减正确：7 月旧新闻 23–30 分，当天的 77–81 分。

**[[流式对话]]** —— 本地起了个假的 OpenAI 兼容 SSE 服务端到端验：分块推送、热点上下文正确注入 system prompt、模板生效、Markdown 逐字渲染。

**RSS / Atom 解析** —— 本地 fixture 服务器喂了两种格式的样本，包括故意用不同字段名的 JSON。

## 没验到的

**Hacker News / GitHub / arXiv** —— 开发容器的网络策略把这三个域名全挡了（curl 直连也是 403），解析逻辑没跑过真实响应。

它们和已验证的源共用同一套 XML/JSON 解析层，风险不算高，但**第一次在本机跑起来时要留意这三个源的角标**，标红了点开看错误信息。

## 测试中揪出的真 bug

**Atom 的作者字段取不到。** RSS 2.0 里 `<author>` 是文本节点，Atom 里是 `<author><name>编辑部</name></author>` 嵌套结构。原来的 `textOf(item.author)` 对后者返回空串。

```ts
// 修复后：两种结构都认
function extractAuthor(item: FeedItem): string | undefined {
  const raw = item.author ?? item["dc:creator"];
  if (typeof raw === "string") return raw.trim() || undefined;
  const first = Array.isArray(raw) ? raw[0] : raw;
  if (first && typeof first === "object") {
    const name = (first as Record<string, unknown>).name;
    return (textOf(name) || textOf(first)).trim() || undefined;
  }
  return undefined;
}
```

**教训**：用 fixture 覆盖同一协议的多种方言（RSS 2.0 vs Atom）是值得的 —— 光测一种格式，另一种的字段静默丢失，页面上看不出来，因为作者字段本来就是可选的。

## 怎么复现这些测试

fixture 服务器和 mock LLM 的脚本没进仓库（在临时目录里）。要重做的话思路是：

1. 起个本地 HTTP 服务，分别在 `/rss`、`/atom`、`/aihot` 返回样本数据

3. `AIHOT_BASE_URL=http://localhost:3222` 指过去
4. mock LLM 就是个按固定间隔往外 `write` SSE chunk 的 server，`OPENAI_BASE_URL` 指过去

值得的话可以整理成 `workbench/scripts/` 下的正式测试。
