# 热点聚合

[[AI 工作台]] 左半边。把五个来源不同、量纲不同的数据并成一张可排序的榜。

## 五个数据源

| 源 | 内容 | 热度依据 | 需要 key |
| --- | --- | --- | --- |
| [[数据源 - AI hot\|AI 热榜]] | 中文 AI 热榜 + 每日简报 | 项目自带 score | 否 |
| Hacker News | 近 3 天 AI 相关、>20 分的帖子 | points | 否 |
| GitHub | 近 60 天新建、>100 star 的 AI 仓库 | star 数 | 可选 |
| arXiv | cs.AI / cs.LG / cs.CL 最新论文 | 发布时间 | 否 |
| RSS | 量子位、机器之心（可换） | 榜位 + 时间 | 否 |

## 三个设计取舍

### 单源容错，不要一损俱损

所有源 `Promise.all` 并行拉，每个源自己 try/catch。某个源挂了只在面板上标红一个角标并列出原因，其余照常出结果。

理由很实际：这些都是别人家的接口，随时可能 403、限速、改结构。要是一个挂了整张榜就空，这东西没法天天用。

```ts
const results = await Promise.all(
  collectors().map(async (run) => {
    try { return await run(); }
    catch (err) { return { source: "unknown", items: [], error: String(err) }; }
  }),
);
```

### 热度分用 log 归一，不用线性

各家量纲差太远：HN 是几百分，GitHub 是几万 star，arXiv 干脆没有热度。统一压到 0–100：

```ts
function normalizeScore(raw: number, saturationPoint: number): number {
  const ratio = Math.log1p(raw) / Math.log1p(saturationPoint);
  return Math.round(Math.min(1, ratio) * 100);
}
```

**为什么必须是 log**：线性归一的话，一个 19 万 star 的 TensorFlow 会把其他所有条目压到个位数，榜单看起来就只有一条。log 让"500 分的 HN 帖"和"5000 star 的新仓库"落在可比的区间。

各源的饱和点：HN 500 分、GitHub 新仓库 5000 star、AI 热榜 score 30。

### 时间衰减，防止旧新闻常年占榜

24 小时内不衰减，之后一周内线性降到 40%，不再往下掉。

```ts
const factor = Math.max(0.4, 1 - (ageHours - 24) / 168);
```

保底 40% 是刻意的 —— 一篇两周前的重磅论文仍然比今天一条平庸新闻有价值，不该被时间彻底抹掉。

实测效果：AI 热榜里 7 月的旧新闻掉到 23–30 分，当天的是 77–81 分。

## 其他

- **去重**按 URL 的 sha1 前 16 位，同一条被多个源收录时保留分高的那条
- **缓存**服务端进程内 5 分钟，前端每 5 分钟自动刷新，右上角"刷新"按钮强制穿透缓存
- 多实例部署时各实例各缓存一份，数据量不大，可以接受

## 加一个新源

在 `lib/sources/` 写个返回 `HotSourceResult` 的函数，注册到 `index.ts` 的 `collectors()`。就这两步。

```ts
export type HotSourceResult = {
  source: string;
  sourceLabel: string;
  items: HotItem[];
  error?: string;   // 有值就在前端标红，不影响其他源
};
```
