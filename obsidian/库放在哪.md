# 库放在哪

**结论：`~/Obsidian`。别放 `~/Documents`，更别放 iCloud。**

两个独立的约束，各自能废掉 [[同步方案]] 的一半：

| 位置 | 出什么事 | 严重程度 |
| --- | --- | --- |
| iCloud Drive | 「优化储存空间」抽走 `.git` 里的 object → **仓库损坏** | 会丢数据 |
| `~/Documents` | TCC 隐私保护挡住 launchd → **自动同步静默失效** | 不丢数据，但自动化白配 |
| `~/Obsidian` | 都不沾 | ✅ |

## 约束一：`~/Documents` 会废掉自动同步（2026-08-08 实测）

这个坑比 iCloud 那个**隐蔽得多**，因为它不报错、不丢数据 —— 你手动 `git pull` 一切正常，
只有定时任务在后台静默地每次都失败。不专门去验证，可能几周后才发现笔记一直没更新。

### 症状

```
$ cat /tmp/com.lee.obsidian-pull.err
fatal: Unable to read current working directory: Operation not permitted
fatal: Unable to read current working directory: Operation not permitted
...（每次触发一条）

$ launchctl list | grep obsidian
-	128	com.lee.obsidian-pull      ← 退出码 128，跑了但每次都死

$ git -C ~/Obsidian/AI工作台 pull
Already up to date.                ← 手动跑完全正常
```

### 原因

macOS 的 **TCC**（隐私保护）把 `~/Documents`、`~/Desktop`、`~/Downloads` 列为受保护目录。
访问它们需要授权，而授权是**按「负责进程」发放的**：

- 你在终端里跑 git → 负责进程是终端，终端早就被你授权过 → 通过
- launchd 直接拉起 git → 负责进程就是 git 自己，没有任何授权 → **EPERM**

git 启动时会调 `getcwd()`，读不出路径就直接 fatal，压根走不到 pull。

> ⚠️ **注意「后台项目」开着不代表有权限。** 系统设置 → 通用 → 登录项与扩展 → 后台 里
> 那条 `git` 开关是开的，任务也确实在跑（错误日志里一次触发一条），
> 但**能运行**和**能访问受保护目录**是两套独立机制。别被这个开关误导。

### 怎么确认是它

对照实验，只改一个变量 —— 把同样的任务装到不受保护的路径下：

```bash
mkdir -p ~/Obsidian
LABEL=com.lee.tcc-test FOLDER_NAME=_probe ./scripts/setup-obsidian-sync.sh ~/Obsidian
```

跑通了就说明问题在路径，不在 git、网络或 plist。实测确实如此。

清理：

```bash
launchctl unload ~/Library/LaunchAgents/com.lee.tcc-test.plist
rm -f ~/Library/LaunchAgents/com.lee.tcc-test.plist
rm -rf ~/Obsidian/_probe
```

### 为什么不选「给 git 开完全磁盘访问权限」

那是另一条路：系统设置 → 隐私与安全性 → 完全磁盘访问权限 → 加入 `/usr/bin/git`。库不用动。

没选它的原因：要手工配一次、给 git 开了全盘读权限（范围过大）、系统更新后有时会掉。
把库挪到不受保护的位置是一次性的，之后什么权限都不用管 —— 自动化要可靠就别依赖手工授权。

## 约束二：iCloud 会毁掉 git 仓库

iCloud 的「优化 Mac 储存空间」会把不常访问的文件抽走，本地只留几百字节的 `.icloud` 占位符。

对文档没问题，对 git 仓库是灾难：

- `.git/objects/` 里的文件被抽走 → 仓库损坏
- 多设备同步 → iCloud 在 `.git` 里生成「XXX 2.md」冲突副本，索引直接乱
- iCloud 不理解 git 的原子性，可能只同步半个写入

Obsidian 官方也不建议库放 iCloud。

### 先确认要不要处理

```bash
if [ -L ~/Documents ]; then
  echo "iCloud 同步开着 ⚠️  →  $(readlink ~/Documents)"
else
  echo "没开 ✅"
fi
find ~/Documents -name '*.icloud' 2>/dev/null | wc -l   # 0 才干净
```

开启「桌面与文稿文件夹」同步后，macOS 会把 `~/Documents` 变成指向
`~/Library/Mobile Documents/com~apple~CloudDocs/Documents` 的软链，用 `-L` 判断比翻设置界面准。

> **2026-08-07 实测本机：没开，占位符 0。** 所以这条约束这次没触发 —— 但库仍然得从
> `~/Documents` 挪走，因为约束一。

> ⚠️ **别去关「桌面与文稿文件夹」开关。** 关掉时 macOS 会撤走 iCloud 上的副本、
> 本地 `~/Documents` 变空，这是丢数据的经典操作。挪库就好，开关别动。

> ⚠️ 终端里没有 `~/文稿` 这个路径。「文稿」只是 Finder 的中文显示名，真实路径是 `~/Documents`。

## 搬迁步骤

顺序：**下载 → 复制 → 校验 → 切换 → 最后才删**。全程用 `cp` 不用 `mv`。

**1. 退出 Obsidian**（⌘Q，不是关窗口 —— 运行时有文件锁和未落盘的缓存）

**2. 如果在 iCloud 里，先强制下载**

Finder 右键库文件夹 →「立即下载」，然后确认没有残留：

```bash
find ~/Documents/Obsidian -name '*.icloud' | head    # 必须无输出
```

不在 iCloud 里就跳过这步。

**3. 只搬笔记，跳过 `AI工作台`**

```bash
rsync -a --exclude='AI工作台' --exclude='_probe' ~/Documents/Obsidian/ ~/Obsidian/
```

⚠️ **别用 `cp -R` 连 `AI工作台` 一起搬。** 那是 sparse checkout 出来的 git 副本，
第 6 步会在新位置几秒钟重新生成，没必要搬。硬搬还会撞上这个：

```
cp: /Users/lee/Obsidian/AI工作台/.git/objects/pack/pack-xxx.idx: Permission denied
cp: /Users/lee/Obsidian/AI工作台/.git/objects/pack/pack-xxx.pack: Permission denied
```

git 把 pack 文件建成只读（444），目标端只要已经存在同名文件，`cp` 就覆盖不了 ——
命令跑第二次、或者第一次中断后重跑，必然撞上。

搬之前先确认旧的那份没有未提交的改动：`git -C ~/Documents/Obsidian/AI工作台 status --porcelain`
（无输出＝干净，可以直接丢弃）。

**4. 校验（两边都排除 `AI工作台` 再比）**

```bash
echo "旧：$(find ~/Documents/Obsidian -type f -not -path '*/AI工作台/*' | wc -l) 个文件"
echo "新：$(find ~/Obsidian -type f -not -path '*/AI工作台/*' -not -path '*/_probe/*' | wc -l) 个文件"
```

**5. Obsidian 里切过去** —— 左下角库图标 → 打开另一个库 → 打开本地库 → 选 `~/Obsidian`

**6. 重配同步**

```bash
cd ~/code/cangjie-skill
./scripts/setup-obsidian-sync.sh ~/Obsidian
```

最后一行要出现 `✓ 定时任务已注册并实测跑通`。

**7. 用一整天确认无误，再删旧库**

```bash
rm -rf ~/Documents/Obsidian
```

## 为什么这步没写成脚本

[[同步方案]] 里那个配置脚本敢写成一键的：幂等、只读远端、错了能重来。

搬库不一样 —— **它动的是你唯一一份知识库**，而且依赖 iCloud 下载状态这种脚本判断不可靠的东西。
写成一键脚本等于把「下载完了吗」「文件数对得上吗」这些必须人眼确认的判断藏进黑盒。

能自动化的和不该自动化的要分清楚：前者是可重复、可回滚的配置，后者是一次性、动真实数据的迁移。

## 挪完之后

`~/Obsidian` 不在任何云同步里，整个库要多设备同步得另想办法：

- **Obsidian Sync**（官方收费）—— 理解 Obsidian 的文件结构，不跟 git 打架
- **库根目录做成私有 git 仓库** + Obsidian Git 插件自动 commit/push
- **Syncthing** —— 免费点对点，要自己配

跟 [[同步方案]] 不冲突：那个管的是 `AI工作台/` 这一个子目录，上面这些管整个库。
