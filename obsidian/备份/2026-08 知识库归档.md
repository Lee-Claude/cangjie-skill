# 2026-08 知识库归档

> 每月首次任务前的自包含备份——内容是摘要抄录，不是指针，方便以后做数据迁移时不用满仓库翻。规则见仓库根目录 `CLAUDE.md`「每月归档」一节，这是第一篇，把这次之前积累的记录一起归档进来了。

## 踩过的坑

### iCloud 把 git 仓库拖坏

macOS「桌面与文稿文件夹」同步开着的话，`~/Documents` 就在 iCloud Drive 里。iCloud 的「优化储存空间」会把不常访问的文件抽成占位符，`.git` 里的 object 被抽走就是仓库损坏；多设备同步还会在 `.git` 里产生冲突副本。Obsidian 官方也不建议库放 iCloud。关键是别去关「桌面与文稿文件夹」开关（会丢数据）——把 git 检出目录挪到不受保护的路径就够了，不用整库搬家。详见 [[同步方案]]。

### sparse checkout 多一层嵌套

sparse checkout 保留仓库内的路径结构，笔记实际在 `~/AI工作台/obsidian/热点聚合.md`，多一层 `obsidian/`。唯一能去掉这层的办法是开一个只含笔记的 orphan 分支，但那样库里的副本就变成只读的——在 Obsidian 里改了笔记 push 回去，下次同步会被覆盖。知识库要随手改，为了少一层面包屑牺牲双向编辑不划算，所以保留这层嵌套。详见 [[同步方案]]。

### clone 忘记带 `-b`，脚本就找不到

`git clone` 不带 `-b` 默认拿 `main`，而同步脚本本身只在功能分支上，会直接报 `no such file or directory`。后来脚本改成自动读取自己所在的分支（`git rev-parse --abbrev-ref HEAD`），但 clone 那一步的分支还是要自己给对。详见 [[同步方案]]。

### macOS 自带 bash 3.2 遇中文全角标点会炸

`$BRANCH）` 里的全角右括号首字节被老版 bash 吞进变量名，撞上 `set -u` 直接退出报 `unbound variable`。Apple 因为 GPLv3 一直没升级自带的 `/bin/bash`（2007 年的 3.2.57 版本），多字节处理有缺陷，bash 5 下不复现。规矩：变量后面跟中文标点一律写 `${VAR}`。详见 [[同步方案]]。

### 检出目录该放哪：TCC 限制 + 之前记录的迁移计划从没真正执行

原计划是把整个 Obsidian 库搬到 `~/Obsidian`（绕开 macOS TCC 对 `~/Documents` 的隐私保护）。但实测这台机器上库根本没搬过，还留在 `~/Documents/Obsidian`——真正部署的是**软链桥接**：git 检出目录单独放在 `~/AI工作台`（TCC 保护范围外），库里放一个 `AI工作台 -> /Users/lee/AI工作台` 的软链接桥接回去。旧笔记里"已完成整体迁移"的说法是错的，已经改写。教训：**不能因为文档写了"已确认"就当真，要拿当天实测的文件时间戳核对**。详见 [[库放在哪]]。

### Claudian 插件 `authentication_failed`——症状和真实原因不是一回事

表面时间线：加了个 NVIDIA key → 插件报 `authentication_failed` → 删掉 key 还是报错，看起来像是加 key 把认证搞坏了。真实原因：Claudian 设置里「Claude CLI 路径」填的是 `/opt/homebrew`，缺了 `/bin/claude`，是个目录不是可执行文件路径。跟 NVIDIA key 纯属时间上巧合。诊断方法：把"账号"和"插件配置"分开验证——终端里直接跑 `claude` 确认账号没坏，再逐字段核对插件里存的路径和真实 `which claude` 输出。**教训：报错发生前"最近改过的东西"不等于"报错的原因"。** 详见 [[Claudian 认证踩坑]]。

## 架构决策

### 为什么是 sparse checkout + launchd，而不是软链库目录 / 整仓库 clone 进库 / Obsidian Git 插件

- 软链仓库目录进库：Obsidian 默认不跟随软链的文件变化（要开「检测所有文件变化」，大库会卡），iCloud 也不同步软链。
- 整仓库 clone 进库：代码会进 Obsidian 的文件树和搜索，一旦 `npm install`，`node_modules` 几万个文件能让索引器卡死。
- Obsidian Git 插件：它管的是库根目录那个仓库，库根不该是这个项目专属的仓库（库里还有别的笔记），子目录里的独立仓库它管不到。

最终方案：`git sparse-checkout set --no-cone '/obsidian/'`（`--no-cone` 很关键，默认 cone 模式会把仓库根目录的无关文件也拉下来），配合 launchd 每 15 分钟 `git pull --rebase --autostash`。详见 [[同步方案]]。

### 云端会话与本机常驻实例：不整体合并

2026-08-28，评估了这个项目（云端/bridge 会话，绑定 `cangjie-skill` 仓库，无持久记忆）跟用户本机常驻 Claude Code 实例（95 skills、3 个 subagent、四层规则体系、独立三层记忆系统）能不能合并成一个。结论是不合并——对方文档自己也建议先只读互通、跑一两周确认不打架，再谈写入。只读互通已经通过 Obsidian 库的软链桥接天然成立（本机实例能读到这个仓库同步过去的笔记）；写入权、规则裁决顺序、命名空间、闸门归谁判，这几件事对方文档列为"合并前必须先谈"，但这边没有对应的技能库/规则体系去谈判，真正能拍板的只有用户本人。作为第一个技术接口点，建了仓库根目录的 `MEMORY.md`，按对方"项目记忆"的规范登记这个项目，供它的"图书管理员"开工前查阅。
