# 希腊房地产快讯

独立小站，聚合几个希腊新闻源的 RSS，筛出房地产相关报道，一个页面看完。代码在仓库根目录 `greek-real-estate-news/`，跟 [[AI 工作台]] 用的是同一套技术栈（Next.js + TypeScript + Tailwind），但业务完全不相关，所以没塞进 `workbench/`，单开了一个项目。

## 为什么是"独立项目"而不是 workbench 里加页面

问用户的时候特意给了这个选项。理由很直接：`workbench/` 是"AI 创作 + 热点聚合"这一个产品，希腊房地产新闻跟它没有任何数据或功能上的耦合，唯一共同点是"都用 RSS/多源聚合"这个模式。硬塞进同一个 Next.js app 会让两个不相关的东西共享 layout、共享部署，以后各自迭代反而互相牵制。分开建项目，`npx next build` 也是各跑各的，互不影响。

## 踩的坑：这个云端会话出不了公网

搭之前想先 `curl` 验证几个候选 RSS 地址（greekreporter.com、ekathimerini.com 等）是不是真的返回 200 + XML。结果不管是 Bash 里的 curl 还是 WebFetch 工具，访问这些域名一律被出网代理拦成 403（`connect_rejected`，网关级别的策略拒绝），白名单只留了 GitHub、npm registry 这些开发相关的域名。

唯一能用的是 WebSearch —— 它走的是 Anthropic 自己的后端，不经过这个会话的出网代理，所以能拿到搜索结果片段（但拿不到完整页面内容，没法验证 XML 格式对不对）。于是数据源选择变成了"根据搜索片段 + 站点技术栈推断"：这几个站大概率是 WordPress，WordPress 惯例的 `/feed/` 路径大概率有效，但具体验证不了。

**应对方式**：没有死磕"必须验证成功才能往下走"，而是把这份不确定性显式地做进代码里——

- `src/lib/feeds.ts` 里每个源都有注释标注"这是猜的，没实测过"
- `src/lib/news.ts` 每个源单独 `try/catch`，一个源挂了不影响其他源，也不让整个页面挂掉
- 首页底部直接渲染"订阅源状态"，每个源 ✅/❌ + 具体报错（比如 `HTTP 403`），不用打开控制台就知道哪个源坏了
- 本地空跑了一次 `npm run dev`：由于同样的出网限制，4 个源全部 403，但页面没崩，正确显示了空态提示和逐条报错——这就验证了"源失效时系统的行为是对的"，即使验证不了"源本身是不是有效的"

这是"能自己验证的绝不甩给用户"和"没法验证的东西不要装作验证过"之间的平衡：架构和容错逻辑是我自己验证过的，但"这几个 RSS 地址到底通不通"这一步物理上做不到，就诚实地留给用户或本机会话去确认，而不是编造一个"已验证"的结果。

## 为什么"刷新"按钮用 Server Action + `updateTag`，不是 API 路由

Next.js 16 这个项目默认没开 Cache Components（`next.config.ts` 里没设 `cacheComponents: true`），走的是"旧模型"：`fetch` 的 `next.tags` + `revalidateTag`/`updateTag`。

一开始写的是 `app/api/refresh/route.ts` 里调 `revalidateTag('news')`，`next build` 类型检查直接报错——这个 Next 版本把 `revalidateTag` 改成两参数了（`revalidateTag(tag, profile)`），单参数形式已废弃。查了 `node_modules/next/dist/docs/` 里带的文档才发现：`revalidateTag(tag, 'max')` 是 stale-while-revalidate，点一下刷新按钮不一定马上看到新内容，得等下一次访问才生效；`updateTag(tag)` 才是"立即失效，下次请求等新数据"，但**只能在 Server Action 里调**，不能在 Route Handler 里用。

这个 Next.js 版本相比训练数据里的版本改动很大（`AGENTS.md` 里专门有提示，让写代码前先看 `node_modules/next/dist/docs/`），这次踩坑就是没查文档直接凭记忆写，类型检查当场报错——算是这句提示应验了一次。最后把 `api/refresh/route.ts` 删掉，改成 `src/app/actions.ts` 的 Server Action，`RefreshButton` 客户端组件里直接 `import` 调用，`router.refresh()` 触发重渲染。

## 数据怎么"实时"

严格意义上做不到真实时——RSS 本身就不是推送的。用的是 Next.js ISR：`export const revalidate = 300`，5 分钟自动刷新一轮；手动点"刷新"能立即穿透缓存。对新闻聚合这个场景，5 分钟粒度够用，没必要上 WebSocket 或轮询这种更重的方案。
