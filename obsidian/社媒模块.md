# 社媒模块

[[AI 工作台]] 的第三个视图。对应参考项目 [oyorf/person_dashboard](https://github.com/oyorf/person_dashboard)
里"社媒洞察 / 抖音数据 / 公众号"这三块——[[知识星图]] 那篇笔记里说过，这三块作者自己的公开
仓库都没有实现代码，只能照着效果自己设计。

## 为什么不接官方 API

**不是技术上做不到，是这一轮做了也没法验证。**

- 抖音开放平台的"创作者数据"权限（粉丝数、播放量这些）通常要企业资质审核，个人开发者
  申请周期长、不一定过。
- 微信公众平台的图文分析接口（阅读数、分享数）大多只对认证服务号开放，普通订阅号拿不到。
- 就算申请到了，OAuth 授权流程、access_token 刷新、接口限流这些逻辑，没有真实凭证我这边
  完全没法跑通测试——写出来的代码只能是"看起来应该对"，跟前两个模块"构建 + API 测试 +
  截图验证"的标准比，是不合格的。

所以选了一条这次能完整自测的路：**本地文件驱动**。

## 三个子模块，两种存储方式

### 社媒洞察 —— Markdown 笔记

跟知识图谱共享同一个 vault，但读的是 `obsidian/insights/` 子目录，**不参与图谱**：

- 不需要 wikilink 解析、不需要出现在关系图里——这些是"研究简报"，跟双链笔记性质不同
- 特意不复用 `lib/vault/read.ts`，另开一个 `lib/social/insights.ts`：为了一个子功能
  去改造已经验证过的核心 vault 读取逻辑，风险划不来
- frontmatter 约定 `title` / `platform` / `period` / `created` / `tags`

写了一篇示例笔记 `insights/2026-08-09-AI工作台赛道观察.md`，内容是这次调研过程本身的
观察——参考项目"截图好看但核心模块不开源"这件事，正好是个真实的案例，不是空洞占位符。

### 抖音数据 / 公众号 —— 约定路径的 JSON

`data/social/douyin.json`、`data/social/wechat.json`，仓库自带脱敏 demo 数据
（`demoMode: true`）。想接真实数据：

- 手动导出、按 JSON schema 填数据，直接覆盖这个文件
- 或者以后写个同步脚本，定期从后台拉数据写进去——前端完全不用改，读的是同一个文件
- 想放别处：设 `DOUYIN_DATA_PATH` / `WECHAT_DATA_PATH`

文件不存在时 API 返回 `200 { data: null }`，前端渲染"还没有数据，格式参考…"的引导文案，
不是报错崩溃——[[热点聚合]] 里"单源容错"的思路在这里也适用：没数据是正常状态，不是异常。

## 两个技术细节

**折线图是手写的，不是 recharts。** `components/social/MiniChart.tsx`，一段 SVG path
加几个点，~40 行。跟 [[知识星图]] 的力导向图一个原则：这个量级的可视化需求，没必要为它
引入一整个图表库。

**demo 数据要写得像真的，不是占位符。** 抖音 7 天播放趋势用了有起伏的真实曲线（不是一条
平线），公众号三篇文章阅读量刻意不同（5680 / 3420 / 2150），这样排序、图表渲染这些逻辑
才有东西可验证——如果 demo 数据全是 0 或者全一样，很多 bug 会被数据本身掩盖掉，截图看着
"好像没问题"实际什么都没测出来。

## 接下来

真要自动拉官方数据，需要先谈清楚：申请哪个平台的什么权限、账号是企业还是个人、数据多久
同步一次。这些是你这边的事，我这边到时候再接同步逻辑。
